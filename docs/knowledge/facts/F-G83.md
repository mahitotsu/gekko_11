# F-G83. DPoP に対応する認可サーバーは、公開クライアントの更新トークンを鍵に結ぶ。画面でコードを動かされると、取り出せない鍵でも安全を保てない

5 節は、DPoP の proof を示した公開クライアントに出す更新トークンを、その公開鍵に結ぶことを MUST とする。更新のときに、同じ鍵の proof を求める。
11.4 節は、攻撃者が画面でコードを動かせると、DPoP の安全は保証されないとする。取り出せない鍵でも、次のことができる。
- クライアントがオンラインの間、新しい proof を作って要求を送る。
- 未来の時刻の proof を先に作り、トークンと一緒に持ち出す。
- 利用者の操作が要らない認可（silent）を新しく始め、受け取った認可コードで、攻撃者の鍵にトークンを結ぶ。すると、クライアントがオフラインでも、攻撃者の端末からトークンを使える。

そのため、DPoP を使っても、信頼できないコードを動かさない対策が要るとする。CSP を第 2 の守りにできるとする。
