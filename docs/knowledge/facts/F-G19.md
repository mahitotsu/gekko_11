# F-G19. RFC 9421 は、HTTP メッセージの署名を定める。中継者が通信を作り直すと、検証に失敗する

HTTP メッセージの一部（フィールドや、メソッド、URI などの導出された構成要素）に対する署名を作り、検証する仕組みである。仕様は、エンドツーエンドの完全性と真正性を提供すると述べる（§1）。TLS が接続単位でしか保証できないことが、動機である。

中継者が、フィールドの並べ替えなど、意味を変えない変換をしても、署名は耐えるべきである（§1.3）。しかし、被覆するフィールドを解析して直列化し直したり、導出された構成要素の値を変えたりすると、検証が失敗する（§1.3）。署名が示すのは、署名者が署名した構成要素である。署名者が、内容を書き換えた中継者自身なら、書き換えた内容に正しい署名が付く（推定）。
