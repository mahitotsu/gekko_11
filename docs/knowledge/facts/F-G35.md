# F-G35. Auth0 の代理のトークンの交換は、出されたトークンの結び付けを確かめず、替えを頼む者の proof か証明書に結び直す

Auth0 は、RFC 8693 の交換（`urn:ietf:params:oauth:grant-type:token-exchange`）で、代理のトークンを出す。`act` は入れ子になり、委任の連鎖は 5 段までである。DPoP と mTLS の送信者の結び付けに対応し、DPoP の対応する種類の表に、交換の要求が載っている。mTLS は、秘密を持つクライアントだけで使え、上位のプランが要る。

交換について、Auth0 は「中間のサービスが、元の持ち主の鍵や証明書を持つことを、暗号で確かめられない」とする。そのため、「交換の間に、元のトークンの結び付けを確かめ直さない」。中間のサービスが、交換の要求で正しい DPoP の proof か証明書を示すと、出すトークンはその鍵に結ばれ、`token_type` は `DPoP` になる。どちらも示さなければ、元のトークンの結び付けに関わらず、結び付けのない Bearer のトークンを出す。DPoP の proof が元のトークンの鍵と合うかは、中間のサービスが自分で確かめる。

DPoP と、独自の交換（Custom Token Exchange）が、一般提供か早期提供かは、読んだ範囲では確かめていない。
