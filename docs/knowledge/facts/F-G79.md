# F-G79. Keycloak 26.8.1 は、設定と小さなマッパーで、公開クライアントに at+jwt、cnf.jkt、固定の sub、may_act、確認済みの属性、1 つの aud を持つトークンを出せる。prompt=none で別の宛先のトークンも受け取れる

- `access.token.header.type.rfc9068` で、`typ` が `at+jwt` になる。
- `dpop.bound.access.tokens` で、DPoP の proof のない要求を断り、`cnf.jkt` を付ける（`kc-jkt-type` という欄も付く）。
- realm の取り込みで利用者の `id` を決めると、`sub` がその値になる。
- 固定値のマッパーの JSON の型で `may_act` を、利用者の属性のマッパーの JSON の型で確認済みの属性を載せられる。`${環境変数}` で値を差し込める。
- 既定のスコープを定めずに `basic` だけを置くと、`aud` は宛先のマッパーの 1 つになる。役割を ID トークンに載せるには、`fullScopeAllowed` を真にする。
- 任意のスコープを分けると、同じログインのまま `prompt=none` で、別の宛先のトークンを受け取れる。
- `use.refresh.tokens` を偽にすると、更新のトークンを出さない。真にしたときの動きは F-G86 にある。
- マッパーから読めるトークンの `id` は、出すトークンの `jti` と一致する。`System.out` の行は、そのまま Pod の標準出力に出る。
