# F-G94. WebAuthn Level 3 の Signal API は、サイトが知る passkey の一覧を端末に伝え、一覧にない passkey を消すか隠させる。ログインした利用者には signalAllAcceptedCredentials を勧める。端末の処理を待たずに返し、passkey の有無をサイトに知らせない

- **3 つの関数:** `signalUnknownCredential`（サイトが知らない識別子）、`signalAllAcceptedCredentials`（利用者の有効な識別子の全部）、`signalCurrentUserDetails`（利用者の名前の更新）。
- **5.1.10.3 節:** 利用者がログインしていて、情報の漏れの恐れがないときは、`signalAllAcceptedCredentials` を `signalUnknownCredential` より勧める。端末は、その RP ID と user handle の passkey のうち、一覧にないものを消すか、以後の認証から隠す。
- **5.1.10 節の注:** 関数は、端末の処理の終わりを待たない。サイトが応答の時間から、利用者の passkey の有無を同意なしに知ることを防ぐためである。
- **5.1.10.1 節:** RP ID は、呼び出し元の effective domain か、その登録可能な親ドメインであればよい（[F-G91](F-G91.md) と同じ規則）。

サイトが「この端末に passkey があるか」を、利用者の操作なしに知る方法は、この規格にはない。
