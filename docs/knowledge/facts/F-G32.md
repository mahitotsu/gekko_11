# F-G32. Keycloak 26.8 は、送信者に結んだトークンを交換に出せるのを、そのトークンを出されたクライアント自身に限る

送信者に結んだトークン（RFC 7800 の `cnf`）を `subject_token` に使えるのは、要求するクライアントが、そのトークンを出されたクライアントと同じときだけである。クライアントは、DPoP で結んだトークンには DPoP の proof を、mTLS で結んだトークンには同じクライアント証明書を示す。クライアントが違うか、proof がないか不正なら、要求を拒む（token exchange の手引き）。

Keycloak は、交換の要求の DPoP の proof の鍵の thumbprint が、`subject_token` の `cnf.jkt` と一致するかを確かめる。要求に正しい proof があれば、替えたトークンも DPoP で結ぶ（DPoP の手引き）。古い token exchange（V1）は、送信者に結んだトークンを扱えず、結び付けなしで出す（比較の表）。

管理者向けの手引き（Server Administration Guide）の DPoP の節は、本文を確かめていない。

この制限を緩め、委任のトークンを、代理の行為者が替えられるようにする要望がある（issue #51205、2026-07-27）。要望は未解決で、ロードマップの Backlog にある（<https://github.com/keycloak/keycloak/issues/51205>、取得日 2026-10-31）。
