# F-G95. passkey の公開の指針は、サインインの後に passkey を作っていない利用者へ作成を促し、断れる選択肢として示し、設定の画面に一覧と作成を置き、サーバーと端末の一覧を Signal API で揃えることを勧める。Signal API は Chrome と Edge の 132、Safari 26 から使え、反映するかは passkey を保存する側が決める

- **web.dev の checklist:** 「サインインの後で、passkey を作っていない利用者には、作るよう促す」。パスワードでサインインした直後に、passkey を自動で作る（conditional create）ことも勧める。サーバーに識別子がない passkey は `signalUnknownCredential()` で知らせ、サーバーから消した後は一覧を知らせる。
- **FIDO Alliance:** 作成は、アカウントに関わる場面（作成、回復、設定）で促す。作るかは利用者が選べるようにする。設定の画面に、一覧、作成、管理を置き、passkey がなければ、そこで作成を促す。OS のダイアログの前後に、何をするかと結果を示す。
- **Chrome の Signal API の解説:** Chrome と Edge の 132、Safari 26 から使える。Google パスワードマネージャーは反映する。ほかの保存する側は、反映するかを自分で決める。
- **Chrome の Conditional Create の解説:** パスワードを保存したパスワードマネージャーが要り、パスワードでのサインインの直後に呼ぶ。
- **読んだ範囲になかったこと:** Windows Hello が Signal API を反映するか。端末に passkey があるかを確かめる方法。
