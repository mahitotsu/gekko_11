# F-G42. Spring Authorization Server は、`actor_token` と `may_act` を確かめる RFC 8693 の交換、交換の要求での DPoP、`tls_client_auth`、証明書に結んだトークンを持つ

Spring Authorization Server は、RFC 8693 の交換を標準で持つ（1.3 以降）。`actor_token` を受け取る。出されたトークンに `may_act` があれば、`actor_token` の `iss` と `sub` が一致することを求め、合わなければ `invalid_grant` で拒む。行為者の連鎖は、トークンを作る部品に渡るが、`act` の入れ子は書かない。`act` は、`OAuth2TokenCustomizer` で書く。

交換の要求に DPoP の proof があれば、それを確かめる（1.5 以降）。文書は、DPoP の proof の公開鍵にアクセストークンを結ぶとする。出されたトークンの `cnf` は、確かめも拒否もしない。

`tls_client_auth` と `self_signed_tls_client_auth` に対応する（1.3 以降）。照合は、既定では Subject DN である。SAN の照合は、証明書の照合の部品を差し替えて行う（文書に例がある）。証明書に結んだトークン（`cnf.x5t#S256`）も出せる。

2025 年 9 月に、Spring Security 7.0 へ移ると告知され、`spring-security-oauth2-authorization-server` として開発が続く。単独の版は 1.5.x が最後である。

出すトークンに `cnf.jkt` を書く処理は、ソースでは見つけていない。動かして確かめる。
