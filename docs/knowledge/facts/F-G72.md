# F-G72. Alloy v1.20.1 が、名前空間ごとの Loki 3.7.8 に、監査の記録を、書いた Pod の印（app、container、namespace）つきで届けた。申込みのハッシュは、Python、Java、TypeScript の 3 か所で同じ値になった

- 5 種類の記録（issue、exchange、tool_call、contract、conversation）が、Loki に届いた。届くまでの遅れは秒の単位で、問い合わせ（`query_range`）で読めた。印は、Alloy の `discovery.relabel` で付けた `app`、`container`、`namespace` で、記録の中の欄とは別である。
- 1 行の JSON は、行末の改行つきで入る。Alloy の `stage.match` で、`"audit"` を含まない行を落とせた。
- JCS で正規化した申込みの SHA-256 は、3 つのサービスで一致した。事務サービスは Python で、鍵を並べ替えた空白のない JSON を使う。保険会社のシステムは Java の java-json-canonicalization、営業 AI エージェントは TypeScript の canonicalize を使う。このシステムの書類は、文字列と整数と入れ子だけである。
- vulnerable の営業 AI エージェントが、認可サーバーを名乗る交換の記録を書くと、Loki には `app=sales-agent` の印で入った。
