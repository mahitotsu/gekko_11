# F-G25. Transaction Tokens（IETF の草案）は、1 つの信頼の領域の中で、利用者と認可の文脈を、短命の署名つき JWT で呼び出しの連鎖に引き継ぐ

Transaction Tokens（Txn-Tokens）は、利用者の識別、ワークロードの識別、認可の文脈を引き継ぐ。引き継ぐ範囲は、信頼の領域（Trust Domain）の中の呼び出しの連鎖である（Abstract）。孤立したワークロードが乗っ取られると、正当な取引のない呼び出し、利用者やワークロードへのなりすまし、パラメータの改変、トークンの盗用が起きうる（§1）。Txn-Token は、取引に結んだ短命の署名つき JWT である（§1）。

信頼の領域ごとに、論理的に 1 つの Transaction Token Service が Txn-Token を出す（§3）。外から見える入口が、外からの認可のトークンを Txn-Token に替えてから、ワークロードへ送る。替えるときは token exchange（RFC 8693）を使う（§5.1、§11.1）。`aud` は信頼の領域の名前で、Txn-Token は、その領域の外では受け付けてはならない。`txn`（取引の識別子）、`sub`、`scope`、`req_wl`（要求したワークロード）、`exp`、`iat` が必須である（§9.2）。有効期間は分の単位か、それより短い（§6）。

草案である。作業部会の文書で、2026-10-30 の時点で、作業部会の合意のあと、IESG への提出を待っている（datatracker）。RFC ではない。
