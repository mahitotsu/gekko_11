# F-G31. RFC 8693 と RFC 9449 は、交換に出されたトークンの鍵を、出した者が持つと示す方法を定めない

RFC 9449（DPoP）は、どの種類のトークン要求にも当てはまり、出すトークンを、要求に付いた proof の公開鍵に結ぶ（§5）。DPoP で結んだトークンを示す先は、リソースサーバーだけを定める（§7.1。認証の方式は origin-server authentication only）。有効性の問い合わせでは、認可サーバーは結び付きを確かめず、リソースサーバーが応答を使って自分で確かめる（§6.2）。token exchange（RFC 8693）と、`subject_token`、`actor_token` には触れない。

RFC 8693 は、`subject_token` と `actor_token` の、鍵の所持の確かめ方を定めない。所持の証明が要るかどうかは、別の取り決めに委ねる（§1）。クライアント認証は OAuth 2.0 の通常の方法で行い、省くと、盗まれたトークンを持つ誰もが、ほかのトークンに替えられると注意する（§2.1）。

identity chaining の草案（-17）は、付録で、鍵を引き継ぐ方式を述べる（付録 B.3）。領域 A の認可サーバーが、クライアントの `cnf` を `requested_cnf` として領域 B に渡し、領域 B は同じ `cnf` を持つトークンを出す。対象は認可サーバーどうしの受け渡しで、トークンを受け取った者が、そのトークンを替える場合ではない。交換で得る認可グラントは、Bearer である（§5.5）。
