# F-G27. MCP の認可仕様（2026-07-28 版）は、クライアントの登録を、事前の登録、Client ID Metadata Documents、Dynamic Client Registration の順に求め、DCR を非推奨にした

2026-07-28 版では、MCP のクライアントは、認可の流れを始める前に、3 つの登録の仕組みのどれかで client ID を得なければならない（MUST）。全てを扱えるクライアントは、次の順に使う（SHOULD）。
1. 事前の登録
2. Client ID Metadata Documents（CIMD）
3. Dynamic Client Registration（DCR、RFC 7591）
4. 利用者への問い合わせ

CIMD は扱うべき（SHOULD）で、DCR は非推奨になり、扱ってもよい（MAY）にとどまる。2025-11-25 版では、CIMD は SHOULD、DCR は後方互換のための MAY だった。

どちらの版でも、MCP サーバーは、自分を宛先として出されたトークンだけを受け付け、受け取ったトークンを上流の API へ素通ししてはならない。上流の API には、上流の認可サーバーが出した別のトークンを使う（F-G17 と同じ）。クライアントは、リソース指定（RFC 8707）の `resource` を、認可要求とトークン要求の両方に入れなければならない。
