# F-G73. Spring Security 6.5 の OAuth2 Client は、発見の文書を使わずに受け口を 1 つずつ決めると、公開名と内部の名前を分けてログインを通せた。tls_client_auth は、要求の組み立てを明示しないと断る

- `ClientRegistration` に、`authorizationUri` を公開名（ブラウザが行く）、`tokenUri` と `jwkSetUri` を Envoy の出口（内部の名前）、`issuerUri` を公開名で入れた。発見の文書（`.well-known`）は読まない。ID トークンの `iss` は `issuerUri` と照らされ、ログインが通った。
- トークンを受け取る部品（`RestClientAuthorizationCodeTokenResponseClient`）は、既定では、クライアント認証が none、client_secret_basic、client_secret_post のどれでもないと、`IllegalArgumentException` で断る。`setParametersConverter` で要求の組み立てを明示すると、この確かめを通らない。既定の組み立て（`DefaultOAuth2TokenRequestParametersConverter`）は、tls_client_auth のとき `client_id` だけを付ける。
- 戻り先（`redirectUri`）は、公開名の絶対 URL で決めた。内部の名前で呼ばれても、認可の要求には公開名の戻り先が入る。
