# F-G17. MCP の認可仕様は、宛先の検証を求め、受け取ったトークンの素通しを禁じる

MCP サーバーは、OAuth のリソースサーバーとして動く。MCP サーバーは、アクセストークンが自分を宛先として発行されたことを検証しなければならない（MUST）。受け取ったトークンを上流の API に素通しすることは、禁じられている（MUST NOT）。上流の API には、別のトークンを、上流の認可サーバーから受け取る。MCP クライアントは、リソースインジケーター（RFC 8707）の `resource` パラメータを、認可リクエストとトークンリクエストの両方に含めなければならない。宛先を検証しないことと、素通しは、混乱した代理（confused deputy）の問題につながる。アクセストークンは `Authorization` ヘッダーで送り、URI のクエリ文字列に入れてはならない（MUST NOT）。認可サーバーは、短命のアクセストークンを発行すべきである（SHOULD）。

仕様の版は 2025-06-18 である。
