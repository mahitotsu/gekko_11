# F-G78. Keycloak 26.8.1 は、authorization_details を処理する SPI を持つ。部品を登録すると、認可の要求で形を確かめ、アクセストークンと応答に載せる。ただし SPI は内部の扱いで、同じログインの間は前回の値が残る

動かして、次を確かめた。
- `AuthorizationDetailsProcessorFactory` の部品を登録する。製品は、`type` の値と同じ ID の部品を探す（ID が違うと「Unsupported type」で断る）。
- `AuthorizationDetailsParser.registerParser` で、`type` ごとの変換を登録する。登録がないと、トークンの要求が 500 になる。
- 部品が断った形と、知らない `type` は、認可の要求の段階で `invalid_request` になる。
- 通った値は、製品がアクセストークンの `authorization_details` と、トークンの応答に載せる。マッパーは要らない。
- 値はクライアントのセッションに残る。同じログインで次に `authorization_details` なしで求めると、スコープに関わらず、前回の値が載る。新しい値を求めると、置き換わる。
- 起動のときに、この SPI と `protocol-mapper` は internal で、予告なく変わりうると警告が出る（KC-SERVICES0047）。

一般の RFC 9396 への対応を求める議論は、公開の場では未解決である（<https://github.com/keycloak/keycloak/discussions/29340>、要約のみ、取得日 2026-11-05）。ほかの版では確かめていない。
