# F-G93. Keycloak 26.8.1 の管理の API は、利用者の passkey の credentialData に、識別子と COSE の公開鍵を返す。サービスアカウントで読むには、fullScopeAllowed が無効なら、役の範囲の対応づけと、クライアントの役をトークンに載せるマッパーが要る

- `/admin/realms/<realm>/users/<id>/credentials` は、型 `webauthn-passwordless` の資格情報を返す。`credentialData` は JSON の文字列で、`credentialId` と `credentialPublicKey`（CBOR の COSE の鍵）を含む。
- Java の厳密な base64 の読み方（`Base64.getDecoder()`）では、`credentialData` の値を読めなかった。base64url の文字（`-` と `_`）と空白を許すと読めた。どちらが原因かは、値を出さずに直したので、確かめていない。Node.js の `Buffer.from(…, "base64")` は、どちらも受けるので、違いが見えない。
- サービスアカウントの利用者に `realm-management` の `view-users` を与えるだけでは、読めない場合がある。クライアントの `fullScopeAllowed` が無効で、既定の範囲が `basic` だけだと、トークンに役が載らない。そのとき、管理の API は 403 を返す。`clientScopeMappings` で `view-users` を対応づけ、`oidc-usermodel-client-role-mapper` で `resource_access.realm-management.roles` に載せると、読めた。
- サービスアカウントのトークンは、SPIRE の JWT-SVID を、federated-jwt のクライアント認証に示して受け取れた（[F-G81](F-G81.md) と同じ形）。

ほかの版では確かめていない。
