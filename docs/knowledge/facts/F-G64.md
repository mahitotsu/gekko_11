# F-G64. 入口の Envoy が転送のヘッダーを付け、Spring Authorization Server が forward-headers-strategy を framework にすると、ブラウザが公開名で作った DPoP の proof で、トークンを受け取れた

ブラウザは、`htu` を `http://auth.<名前空間>.localhost:<ポート>/oauth2/token` として DPoP の proof を作る。認可サーバーは、クラスタの中で SVID の TLS（https、内部の名前）で受ける。入口が `x-forwarded-proto: http` と `x-forwarded-port` を付け、Host を変えずに渡すと、トークンの要求が通り、A に `cnf.jkt` が入った。

転送のヘッダーを付けない場合は、確かめていない。`framework` は、誰が付けた転送のヘッダーも信じるので、クラスタの中の呼び手が付けても効く。影響は、受け取る URL の見かけ（DPoP の `htu` との照合）に限られる。
