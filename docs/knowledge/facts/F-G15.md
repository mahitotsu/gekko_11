# F-G15. RFC 9068 は、アクセストークンに typ(at+jwt)、aud、exp などを必須にし、受け取る側に検証を求める

JWT 形式のアクセストークンの規則である。
- **発行側:** `typ` に `at+jwt` を入れなければならない（MUST、§2.1）。署名が必須で、`alg` に `none` を使ってはならない（§2.1）。`iss`、`exp`、`aud`、`sub`、`client_id`、`iat`、`jti` を含める（§2.2）。リソースごとに区別できる `aud` を使う（§5）。
- **受け取る側（リソースサーバー）:** `typ` が `at+jwt` であることを検証し、違えば拒否する（MUST、§4）。目的は、ID トークンをアクセストークンとして受け入れる事態を防ぐことである（§2.1、§5）。`aud` に自分のリソース識別子が含まれなければ拒否する（MUST、§4）。`alg` が `none` なら拒否し、認可サーバーが提供する鍵だけを使う（§4）。`iss` が完全一致し、現在時刻が `exp` より前であることを確かめる。時計のずれの猶予は、数分程度まで許される（§4）。
- **`sub`:** 資源所有者が関与するなら、所有者の識別子を使う。関与しない場合（client credentials など）は、クライアントの識別子を使う。どちらも推奨である（SHOULD、§2.2）。
- **認可情報:** `scope` は、`aud` のリソースで意味を持つ値だけにする。複数のリソースで曖昧になる場合は、トークンを発行してはならない（§2.2.3、§3）。
