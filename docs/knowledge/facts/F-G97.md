# F-G97. Keycloak 26.8.1 は、アプリが `kc_action=delete_credential:<資格情報の ID>` で頼むと、名前を示した確認の画面を出し、本人が確かめると、その passkey だけを消して kc_action_status を返す。重ねての登録を断る設定は既定で無効で、有効にすると、登録の画面に既存の passkey の除外が入る

- **頼み方:** 認可の要求に `kc_action=delete_credential:<ID>` を付ける。ID は、管理の API の資格情報の `id`（ログインサーバーの中の UUID）で、passkey の識別子ではない。
- **確認の画面:** 資格情報の名前（`userLabel`）を示し、「Confirm deletion」と「Decline」を出す。文言は、realm の `localizationTexts` の `deleteCredentialTitle`、`deleteCredentialMessage`、`doConfirmDelete`、`doDecline` で替えられる。
- **結果:** 確かめると、指定した passkey だけが消え、戻り先に `kc_action=delete_credential` と `kc_action_status=success` が付いた。
- **ログインし直し:** パスワードでログインした直後のセッションでは、ログインし直しを求めなかった。時間が経った後の振る舞いは、確かめていない。
- **重ねての登録:** `webAuthnPolicyPasswordlessAvoidSameAuthenticatorRegister` は既定で `false` だった。`true` にすると、登録の画面の `excludeCredentialIds` に、その利用者の既存の passkey の識別子が入った。除外された passkey を持つ端末で、ブラウザが作成を断ったときの画面の振る舞いは、この確かめの範囲の外である。

ほかの版では確かめていない。
