# F-G50. Spring Authorization Server は、示された証明書の連鎖が 1 枚だと `self_signed_tls_client_auth` とみなす

標準の変換の部品は、連鎖の長さで認証の方式を決める。1 枚なら `self_signed_tls_client_auth`、2 枚以上なら `tls_client_auth` である。登録した方式と違えば、`invalid_client` で拒む。

SPIRE の SVID は、1 枚で示される（F-G52）。そのため、`tls_client_auth` で登録したサービスは、そのままでは認証できない。このリポジトリは、変換の部品を差し替え、常に `tls_client_auth` として扱う。連鎖は、TLS の層が SPIRE の bundle で確かめる（`SpiffeCertificateConverter`）。

標準の照合は Subject DN を見る（F-G42）。SVID の Subject はサービスによらず同じなので（F-G52）、照合の部品も、SAN の URI を見るものに差し替える（`SpiffeCertificateVerifier`）。
