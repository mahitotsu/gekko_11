# F-G54. SVID が入れ替わると、前の証明書に結んだトークンは拒まれ、入れ替わった直後には、正規の連鎖も一時的に拒まれる

入れ替わる前に insurer-mcp の SVID に結んだ C は、入れ替わった後に拒まれた。insurer-backend の token-guard の理由は、「相手の証明書に結ばれていない」だった。認可サーバーは、SVID のファイルが替わっても、そのまま応答を続けた（Spring Boot の SSL bundle の読み直し）。

入れ替わった直後の 1 回は、insurer-mcp が、営業 AI エージェントの B を同じ理由で拒んだ。30 秒後には通った。推定: Envoy は、入れ替わる前の証明書でつないだ接続を使い続け、B は新しい証明書に結ばれていた。この推定は、接続の記録で確かめていない。

トークンの有効期間（5 分）の間に SVID が入れ替わると、結んだトークンは使えなくなる。段 1 で、接続の寿命の上限か、拒まれたときの取り直しを決める。
