# F-G33. RFC 8705 は、証明書によるクライアント認証と、トークンの証明書への結び付けを、別の仕組みとして定める

クライアント認証の方法は、PKI の証明書の連鎖による `tls_client_auth`（§2.1.1）と、自己署名の証明書による `self_signed_tls_client_auth`（§2.2.1）である。トークンエンドポイントのほか、有効性の問い合わせと失効のエンドポイントにも使える（§1）。

認可サーバーは、出すアクセストークンを、クライアント証明書のハッシュ（`cnf` の `x5t#S256`）に結ぶ（§3、§3.1）。リソースサーバーは、TLS の層から得た証明書が、トークンに結んだ証明書と一致するかを確かめ、違えば拒む（MUST、§3）。結び付けとクライアント認証は、補い合うが、一緒に使わなくてもよい別の仕組みである（§1、§3）。公開クライアントでも、自己署名の証明書で結び付けだけを使える（§4）。ウェブブラウザは、サーバーが証明書を求めると、利用者に煩わしい証明書の選択画面を出すことが多い（§5）。

token exchange（RFC 8693）には、読んだ範囲（§1〜§5）で触れていない。
