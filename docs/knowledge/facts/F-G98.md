# F-G98. Windows の VS Code に内蔵されたブラウザと Windows Hello で、passkey の作成、passkey でのログイン、同じ passkey での申込みの署名ができた。アプリで保険会社の登録を消し、Signal API で一覧を伝えても、Windows の passkey は残り、使うと unknown user になった。作り直すと置き換わった

- **できたこと:** パスワードでのログインの後の作成（名前を尋ねられない）、「パスキーでログイン」での passkey のログイン、同じ passkey での申込みの署名。
- **消した後:** 顧客のアプリの「消す」で、ログインサーバーの登録を消した。顧客のアプリは、ログインの後に Signal API（`signalAllAcceptedCredentials`）で一覧を伝えるが、Windows の passkey は残った。その passkey でのログインは、ログインサーバーが知らないので「unknown user」になった。
- **作り直し:** 同じ利用者で作り直すと、Windows の古い passkey は新しいものに置き換わり、古いものはたまらなかった。
- **区別できないこと:** Signal API の効かなかった理由は、この操作からは分からない。考えられるのは、Windows Hello の側で反映しないことと、VS Code の内蔵のブラウザが Signal API を持たないことの 2 つである。ほかのブラウザ（Chrome、Edge）では試していない。
