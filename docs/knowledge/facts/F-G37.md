# F-G37. Curity Identity Server は、交換の流れでも DPoP を使え、SAN の URI（SPIFFE ID）で mTLS のクライアント認証ができる

Curity は DPoP に対応し、DPoP を使える流れの一覧に、トークンの交換を挙げる。交換は、`actor_token` を受け取り、委任に使える。交換の中身は、トークンの手続き（JavaScript）で書く。交換でもクライアント認証を強く勧める。

mTLS のクライアント認証では、SAN の URI の項目で照合でき、SPIFFE ID を使う例がある（7.2 以降）。証明書に結んだアクセストークン（`cnf.x5t#S256`）も出す。商用の製品で、試用の版がある。

結び付けたトークンを、別のクライアントが替えたときの扱い（替える要求の proof に結び直すか）は、本文で確かめていない。検索結果の要約には、結び直すとの記述があった。
