# F-G49. Spring Authorization Server の標準の customizer は、DPoP の `cnf.jkt`、証明書の `cnf.x5t#S256`、交換の `act` の入れ子を、出すトークンに書く

`DefaultOAuth2TokenCustomizers` は、アクセストークンに次を書く。
- 要求に DPoP の proof があれば、proof の公開鍵のサムプリントを `cnf.jkt` に書く。
- `tls_client_auth` か `self_signed_tls_client_auth` で認証したクライアントで、証明書に結ぶ設定（`x509CertificateBoundAccessTokens`）があれば、証明書の SHA-256 を `cnf.x5t#S256` に書く。
- 交換で積んだ行為者を、新しい順に `act` の入れ子で書く。いま替えを頼んだ者が外側になる。

利用者の `OAuth2TokenCustomizer` を登録すると、標準の customizer の後に呼ばれる（両方が効く）。交換では、出されたトークンの `cnf` は引き継がず、替えを頼む要求の proof か証明書で書き直す。このリポジトリの試作では、A は `cnf.jkt`、B と C は替えを頼む者の SVID の `cnf.x5t#S256` になり、C の `act` は insurer-mcp の内側に sales-agent が入った。
