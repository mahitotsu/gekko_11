# F-G106. Astro をルートの workspaces に入れると、ルートの古い Vite と cookie を読んで build が落ちる

- **@tailwindcss/vite:** `M.createIdResolver is not a function` で落ちた。プラグインは、ルートの `node_modules/vite`（5.4.21）を読んだ。Astro が使う Vite は、`node_modules/astro/node_modules/vite`（8.3.8）だった。
- **cookie:** `Named export 'parseCookie' not found` で落ちた。Astro は cookie の ^2.0.1 を求めるが、まとめた出力からは、ルートの cookie 0.7.2（`@modelcontextprotocol/sdk` → express の依存）が読まれた。
- **通った形:** `site/` をワークスペースから外し、自分の `package-lock.json` と `node_modules` を持たせた。Tailwind は `@tailwindcss/postcss` で通した。PostCSS 版で `@import "tailwindcss"` と書くと、Vite がファイルとして探して落ちたので、`@import "tailwindcss/index.css"` と書いた。
- **独立させた後も、ルートに頼っていた:** `site/` の型の検査は、`@types/node` をルートの `node_modules` から読んでいた。`site/` だけを入れる GitHub Actions の Pages のジョブで、`Cannot find module 'node:fs'` などで落ちた。`site/` に `@types/node` を足すと通った。CI では、ルートを入れない別のジョブで `site/` を確かめる。
