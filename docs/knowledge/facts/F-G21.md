# F-G21. RFC 7636（PKCE）は、公開クライアントの認可コードの横取りを、リクエストごとの秘密の値で防ぐ

認可コードグラントを使う公開クライアントは、認可コードの横取り（interception）に弱い。TLS で守られない経路（同じ OS の中のアプリ間の通信など）で、攻撃者が認可コードを横取りし、アクセストークンに替えられる（Abstract、§1）。

PKCE では、クライアントが、認可要求のたびに暗号学的に乱数の code verifier を作る。その変換値（code challenge。S256 なら SHA-256 の BASE64URL）を認可要求で送り、トークン要求で code verifier を示す（§1、§4.1〜§4.5）。サーバーは、受け取った code verifier を変換して、認可コードに結び付けた code challenge と比べ、一致しなければ `invalid_grant` を返す（§4.6）。認可コードを横取りした攻撃者は、code verifier を持たないので、アクセストークンに替えられない（§1）。S256 を使えるクライアントは S256 を使わなければならない（MUST、§4.2）。
