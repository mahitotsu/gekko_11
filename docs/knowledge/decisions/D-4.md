# D-4. 高額や厳格な確認が要る取引には、追加認証を求める

## 理由
窓口は、厳格な確認が要る取引に追加の確認を求める（I-B6）。RFC 9470 が同じ要求を表せる（F-G3）

## 退けた案
常に最強の認証。取引によらない一律の認証。

## 影響
良い: 利便性と強さを両立する。悪い: 閾値の設計が要る。

## 詳しい理由

### 追加確認は、追加認証で同等に保てる
窓口は、厳格な確認が要る取引に、追加の確認を求める（I-B6）。DX では、登録時の本人確認を厳密に行い、取引では追加認証（F-G3）で、認証の強さや新しさを求める。リソースサーバーが `acr_values` と `max_age` で要件を伝え、クライアントが再認証を求める。

**前提:** 認可サーバーが、要件を満たす認証を実際に行える。

### 承認の分離は、同等に保ち、機械的な照合を足せる
承認ワークフローでは、承認者は申請内容を修正できず、差し戻すか取り下げさせる（C-1）。人の承認の強さは、窓口と同じである。内容への署名があれば、提出された内容が承認時のものかを、毎回自動で検証できる。入力ミスと、途中の書き換えが、機械的に見つかる（推定）。

別端末での承認が要る場合は、CIBA（F-G6）が使える。取引を始める端末と、承認する端末を分け、`binding_message` を両方に出して、同じ取引だと確かめさせる。
