# D-17. 記録の監査は、記録を作る者と別の監査サービスが、認可サーバーと事務サービスの記録と突き合わせて行う

## 理由
窓口では、会社が営業員を監査し、記録を保存する（I-F1、I-G1）。記録を作る保険会社のシステムが、自分の記録を確かめても、書き換えは見つからない。第三者の記録と照らしてはじめて、確かめたことになる

## 退けた案
- 保険会社のシステムの中に、監査の画面を置く

## 影響
良い: 保険会社のシステムの記録の書き換えや欠けを、交換の記録とツールの記録で見つけられる。悪い: サービスが 1 つ増える。監査で見つけたことに、人がどう対処するかは、運用に依る

## 詳しい理由
監査サービスは、契約ごとに、3 つの記録を突き合わせる。
- 保険会社のシステムの記録: 署名済みの申込み、提示集合、`act` の連鎖
- 認可サーバーの交換の記録: いつ、誰が、どのトークンを、どの宛先に替えたか
- 事務サービスのツールの呼び出しの記録

監査サービスだけが、SPIFFE ID で、これらを読める（D-16）。監査の画面は、監査の担当だけが見られる。gekko_07 も、業務サービスの自己申告と、認可サーバーの記録を突き合わせる監査サービスを、別に立てていた。
