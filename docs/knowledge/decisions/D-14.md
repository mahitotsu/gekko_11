# D-14. 事務サービスは、MCP の認可仕様に従い、自分宛てのトークンだけを受け付け、上流には別のトークンを使う。宛先は、リソース指定（RFC 8707）で指定させる

## 理由
事務サービスは、営業 AI エージェントから MCP で呼ばれる MCP サーバーなので、MCP の認可仕様が当てはまる。仕様は、宛先の検証と素通しの禁止を求める（F-G17、F-G27）

## 退けた案
受け取ったトークンを、上流の保険会社のシステムへそのまま渡す（素通し）

## 影響
良い: 宛先違いのトークンと、素通しを防げる。悪い: 呼び出しのたびに、トークンを替える手間が要る（D-2）

## 詳しい理由
MCP の認可仕様は、2025-11-25 版でも 2026-07-28 版でも、次の 2 つを求める（F-G17、F-G27）。MCP サーバーは、自分を宛先として出されたトークンだけを受け付ける。受け取ったトークンを、上流へ素通ししない。上流の API には、上流の認可サーバーが出した別のトークンを使う。クライアントは、`resource` を認可要求とトークン要求に入れる（F-G18、F-G27）。
