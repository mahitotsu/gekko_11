# D-3. 委任の範囲は、RAR の `authorization_details` で表す

## 理由
`scope` では、特定の対象などの細かい要件を表せない（F-G2）

## 退けた案
`scope` だけ。取引ごとの `authorization_details`

## 影響
良い: 契約の種類と上限を機械的に適用できる。悪い: 範囲内の誤りは防げない

## 詳しい理由
取引ごとに `authorization_details` を発行すると、取引ごとに承認と発行が要り、発行回数が増える（推定）。RAR は権限の範囲（契約の種類、上限）に使い、取引ごとの内容の承認は、利用者の鍵による署名で行う（D-1）。
