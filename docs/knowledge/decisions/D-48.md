# D-48. 顧客のアプリは Tailwind CSS、監査の画面は Bootstrap 5 で組み、画面の CSP は緩めない

## 理由
デモとして見せる画面は、普及した UI ライブラリで組まれていないと、業務の画面に見えない。物差しは見た目の新しさではない。次の 3 つの区別が一目で分かることである。
- 保険会社が署名し、画面が確かめた内容と、営業 AI エージェントの言葉（確かめていない）の区別。
- 拒んだことや食い違いと、一致の区別。
- secure と、防御を外せる複製（vulnerable）の区別。

顧客のアプリの CSP（G32）は `style-src 'self'` で、要素の style 属性を止める（F-G102）。そのため、位置を style 属性で書く部品（F-G103）は、CSP を緩めないと動かない。Tailwind CSS は、使ったクラスから静的な CSS ファイルを書き出すので、CSP を変えずに使える（F-G104）。部品は、shadcn/ui の Card、Button、Badge、Alert、Table の見た目を写し、Tailwind のクラスだけで描く。これらは位置を決めないので、Radix などの部品の層は要らない。

監査の画面は、Spring Boot と Thymeleaf で描く。Bootstrap 5 の CSS を WebJars で配れば、Java のビルドに Node を持ち込まない。開閉は `<details>` のままにし、Bootstrap の JS の部品は使わない。色のモードは、OS の設定に自動では従わない（F-G105）。そのため、小さなスクリプトをファイルとして配り、`data-bs-theme` を合わせる。

vulnerable の顧客のアプリは、画面の上に「防御を外せる複製」の帯と、今外している画面の防御の ID を出す。帯は、防御を外す受け口と同じく、vulnerable の版のファイル（`web/defenses.ts`）だけが出す（D-24）。監査の画面は、見出しに名前空間を出す。

## 退けた案
- MUI、Chakra、Radix を使う shadcn/ui: 位置を style 属性で書く部品があり、CSP の `'unsafe-inline'` が要る（F-G102、F-G103）。Radix がどこで style 属性を書くかは、確かめていない。
- 2 つの画面を Bootstrap でそろえる: 読み手が覚える部品は 1 つで済むが、React の画面の今の定石から外れる。
- 2 つの画面を Tailwind でそろえる: 2 つの画面の見た目をそろえられるが、監査サービスの Maven のビルドに、Tailwind の CLI（Node）が要る。
- 自前の CSS のまま: 動きは正しいが、業務の画面に見えない。

## 影響
良い: CSP（G32）を変えずに、2 つの画面を普及したライブラリで組める。署名を確かめた内容、AI の言葉、警告が、色と記号と文言で分かれる。記号は CSS の `::before` で出し、テストが読む要素の文に混ぜない。

悪い: 依存が増える（tailwindcss、@tailwindcss/vite、Bootstrap の WebJar）。部品は shadcn/ui を写した自前のものなので、shadcn/ui の更新は取り込めない。監査の画面と顧客のアプリの見た目は、そろっていない。
