# D-12. 顧客のログインは、認可コードと PKCE（S256）で行い、OpenID Connect の ID トークンを受け取る

## 理由
顧客のアプリは秘密を持てない公開クライアントで、認可コードの横取りを PKCE で防ぐ（F-G21）。FAPI 2.0 は、公開クライアントを対象にしない（F-G24）

## 退けた案
FAPI 2.0 Security Profile をそのまま当てはめる。

## 影響
良い: 認可コードを横取りされても、アクセストークンに替えられない。悪い: FAPI 2.0 の形式的な分析による保証は得られない。

## 詳しい理由
FAPI 2.0 は、PAR、S256 の PKCE、送信者に結んだアクセストークンを求めるが、対象は秘密を持つクライアントに限る（F-G24）。このシステムの顧客のアプリは、利用者の端末で動く公開クライアントである。そこで、FAPI 2.0 の求めのうち、公開クライアントにも当てはまる S256 の PKCE を採る。送信者に結んだアクセストークンは、D-7 で別に決める。ID トークンは、利用者の認証についての署名つき JWT で、宛先は顧客のアプリである（F-G22）。サービスを呼ぶ許可には、アクセストークン（D-13）を使う。
