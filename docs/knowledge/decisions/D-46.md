# D-46. 防御の ID は G1〜G32 とし、判断の ID と別の文字にする

## 理由
防御の ID は D1〜D32 で、判断の ID は D-1〜D-46 だった。違いはハイフンだけで、同じ文に並ぶ。例えば「（D30、P-17）」の D30 は防御で、「D-30」は判断である。読み手は取り違えやすく、検索でも分けにくい。

防御は、シナリオの組み立て（リスク R × 手口 A × 防御）の 1 つの軸である。G は guard の頭文字で、ほかの ID（R、A、E、事実の I-・F-G・C-、判断の D-・P-）が使っていない。番号と枝の文字は、そのまま保つ（D3a は G3a、D26 は G26）。

付け替えは、文書、knowledge、コード、テスト、管理の受け口に渡す ID の全てで、同じ変更で行った。

## 退けた案
- **判断の ID を変える:** 判断のファイル名と、全ての文書の参照が変わる。判断は記録なので、ID を使い回さない規則（knowledge/README）とも合わない。
- **変えずに、文で書き分ける:** 書き手が毎回気をつける必要があり、検索では分けられない。

## 影響
良い: 防御と判断を、文字で見分けられる。悪い: 以前のコミットや、この判断より前の記録の読み手は、D1〜D32 が今の G1〜G32 に当たると知る必要がある。
