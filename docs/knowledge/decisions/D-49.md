# D-49. 価値を伝えるサイトを、独立した site/ に Astro で組み、GitHub Pages に出す

## 理由
サイトは、入口と 3 つの章で、17 ページほどになる。1 ページに 1 つの主張を置くので、見出し、章の位置、根拠の枠、前へ／次へを、全ページで同じ部品にしたい。Astro は、部品で組み、静的な HTML を出す。JS を配らずに済む。見た目は、顧客のアプリ（D-48）と同じ Tailwind CSS にし、色の値と部品の考え方をそろえる。

`site/` は、ルートの npm workspaces に入れない。入れると、ルートの古い Vite と cookie を読んで、build が落ちた（F-G106）。依存を分けると、サイトの部品の版を、ほかのパッケージと独立に上げられる。

数字（要件、リスク、手口、防御、シナリオの数）は `site/src/data/facts.ts` に置き、docs の見出しと照らすテストを持つ。正本は docs で、サイトの数字が古くなったら、テストで気づける。

## 退けた案
- 手で書いた HTML: 部品がないので、道案内と根拠の枠を、全てのページで書き写す。
- スライドの道具（reveal.js など）: 1 つの URL に全てのスライドが入り、読み手ごとのページを URL で渡しにくい。
- 文書サイトの道具（VitePress、Docusaurus など）: docs を写す形に寄り、図を主役にしたページを作りにくい。docs と二重に持つことにもなる。
- ルートの workspaces に入れる: build が落ちた（F-G106）。

## 影響
良い: 部品で組めて、出力は静的な HTML だけになる。サイトの依存は、ほかのパッケージの依存と混ざらない。

悪い: `npm ci` と `npm test` を、ルートとは別に `site/` で回す（CI は両方を回す）。依存の版の更新も、`site/` で別に行う。Tailwind は、顧客のアプリが Vite のプラグイン、サイトが PostCSS と、通し方が違う。
