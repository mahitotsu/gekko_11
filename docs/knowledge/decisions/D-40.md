# D-40. 顧客のアプリを、広く使われる部品で組み、確かめる処理は自分のコードに残す

## 理由
広く使われる実装方式に組み込めないと、アーキテクチャの実用性を示せない。画面と OAuth の部品を替えても、信頼の構造は変わらないことを、同じ画面のテストで確かめる。

広く使われる部品だけでは足りない。oidc-client-ts は ID トークンの署名を確かめないので、G21 は自分のコードで行う（F-G88）。案の署名（G22）と確認画面（G23）も、部品に任せない。

## 退けた案
- 独自実装のままにする: 広く使われる方式との組み合わせを示せない。
- CopilotKit: サーバーの Runtime を経由する作りで、ブラウザが A と proof を直接送る構造に合わない。
- Next.js: サーバーを持つ強みは BFF で生きる。BFF を採るまでは要らない。React の部品は、後で移せる。
- BFF へ同時に移す: D-18 の判断と、防御、シナリオ、テストの部品まで変わる。別の判断として扱う（F-G87）。

## 影響
**追記:** BFF に移したので（D-41）、oidc-client-ts は外し、ログインは BFF の openid-client で行う。openid-client も、既定では ID トークンの署名を確かめないので、G21 は BFF の自分のコードで行う。

良い: 普通の React アプリに組み込める形を示せる。`innerHTML` がなくなり、CSP は `self` だけで組める。悪い: 画面のまとめたファイルが大きくなった（約 850 kB）。部品の版に依存し、部品の動きを実機で確かめる必要がある（F-G88）。ブラウザだけで OAuth を完結させる形のままで、RFC 10017 が個人情報を扱うアプリに推奨しない形である（F-G87）。

## 詳しい理由
- **G21 を外す悪い実装:** `nonce` を渡さなければ、部品は照らさない。別のファイルは要らない。
- **A と P:** 保存先を分けた 2 つの `UserManager` で持つ。
- **サインアウト:** RP-Initiated Logout の URL は、部品に任せず自分で組む。確かめられない ID トークンを示さないためである（D-33）。部品が DPoP の鍵も消すので、サインアウトの後は、同じ鍵を使い回さない。
- **CSP:** React に CSP の機能はない。Vite がスクリプトとスタイルを外部ファイルにするので、配信元がヘッダーで `self` を送るだけで済む（G32）。
- **回の順:** 走っている間に決まった答えは、次の回に回す。部品の 1 つの `HttpAgent` で、回を重ねないためである。
