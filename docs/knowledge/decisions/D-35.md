# D-35. 外部に面するログインと ID トークンと A の発行は、Keycloak のログインサーバーに分け、B と C への交換は、Spring の認可サーバーに残す

## 理由
利用者の名簿とログインは、外部に面し、実績のある製品に任せられる部分である。交換の規則は、D-7 の結び直しに要り、Keycloak では成り立たない（F-G32）。Keycloak に交換をさせなければ、この制限と、委任が preview であること（F-G30）に当たらない。分けると、ほかの発行者のトークンを替える RFC 8693 の使い方も、動くもので確かめられる。

## 退けた案
- Spring の認可サーバーに全てを置く: 外部に面する部分が、製品の裏付けのないログインのままで、発行者をまたぐ交換を確かめられない
- 顧客のアプリが、Keycloak のトークンを Spring で A に替える: B と C の処理は変わらないが、公開クライアントの交換を自作する。発行者をまたぐ結び直しを確かめられない
- identity chaining（F-G26）の形で替える: Keycloak が交換をするので、F-G32 に当たる

## 影響
良い: ログインが製品に乗る。発行者が分かれるので、A や ID トークンを奥の段へ出しても通らない（G29）。悪い: サービスが 1 つ増え、起動に 1 分から 3 分かかり、メモリが 1 Gi まで増える。A を替える部分は、自作の取り込みに依る（D-36）。2 つとも保険会社のものなので、信頼の領域をまたぐ検証にはならない。

## 詳しい理由
D-19 は、交換の認可サーバーの製品の判断として残る。
