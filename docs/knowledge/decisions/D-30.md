# D-30. 監査の記録は、各サービスが書き出し、Alloy 1 つが名前空間ごとの Loki に届ける

## 理由
監査サービスが突き合わせる第三者の記録は、記録を作る者が後から書き換えられない場所に置く（D-17）。サービスが自分の記録を持ち、監査サービスが各サービスに問い合わせる形では、記録を作る者が答えを変えられる。各サービスは標準出力に書くだけにし、集める者が別の場所へ運ぶと、書いた者は届いた記録に触れられない。

Alloy の `loki.source.kubernetes` は、Kubernetes の API で記録を読むので、ノードのファイルと特権が要らず、1 つでクラスタ全体を集められる（F-G71）。Alloy が、書いた Pod の印（app、container）を付ける。そのため、記録の中の欄に頼らず、書いた者を決められる（F-G72、D-32）。

Loki を名前空間ごとに分けると、secure と vulnerable の記録が混ざらず、名前空間の隔たり（D-20）を保てる。

## 退けた案
- 監査サービスが、各サービスの記録の受け口を読む: 記録を作る者が、答えを変えられる
- Loki を 1 つにして、名前空間を印で分ける: 名前空間をまたぐ通信が増え、vulnerable の記録の偽装が secure の記録の隣に入る
- Alloy を名前空間ごとに置く: 分ける利点は少なく、資源が増える
- DaemonSet の Alloy が、ノードの記録のファイルを読む: hostPath と特権に近い権限が要る

## 影響
良い: 記録を作る者は、Loki に届いた記録を書き換えられない。書いた者を、Pod の印で見分けられる。悪い: Alloy が 1 つなので、止まると記録が届かない。kubelet の通信が増える（F-G71）。Loki に届いた後の書き換えは、クラスタと Loki を操作できる者なら行え、防がない（D-32）。記録の保存は、教材の規模に合わせた単一のプロセスとファイルである。

## 詳しい理由
- **版:** Loki 3.7.8、Alloy v1.20.1。どちらも公開から 2 週間以上たった版である。
- **送る行:** Alloy は、`"audit"` を含む行だけを送る。Envoy のアクセスログなど、ほかの行は送らない。
- **保存期間:** compactor の保存期間で、7 日とする（F-G70）。期間の根拠は D-32 にある。
- **通信の制限:** Loki の受け口は、logging の名前空間の Alloy と、同じ名前空間の監査サービスだけに開く（NetworkPolicy）。Loki に認証はない。
- **イメージの取り込み:** Loki と Alloy のイメージは、手元の CPU の分だけを書き出してから、クラスタに取り込む（F-G75）。
