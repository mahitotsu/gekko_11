# D-13. トークンは JWT のアクセストークン（RFC 9068）で表し、受け取る側は JWT の実装指針（RFC 8725）に従って検証する

## 理由
受け取る側が、発行元の公開鍵で、署名と項目（`iss`、`aud`、`exp`、`typ`）を毎回機械で検証できる（F-G13〜F-G15）

## 退けた案
中身の見えないトークンを、毎回の問い合わせだけで確かめる。

## 影響
良い: 受け取る側は、発行元に問い合わせなくても検証できる。悪い: 失効がすぐには反映されない。有効期間を短くし、営業 AI エージェントの登録は問い合わせで補う（P-13）

## 詳しい理由
JWT の基本の仕様（RFC 7519）では、`iss`、`sub`、`aud`、`exp`、`typ` は任意である（F-G13）。アクセストークンの規則（RFC 9068）が、これらを必須にする（F-G15）。受け取る側は、許すアルゴリズムを固定し、`aud` と `typ` を検証して、別の種類の JWT との取り違えを防ぐ（F-G14）。
