# D-43. この端末に passkey があるかは確かめず、保険会社の一覧と端末を揃え、作成を促す

## 理由
サイトが、利用者の操作なしに「この端末に passkey があるか」を知る方法は、規格にない（F-G94）。利用者を追跡されないよう、規格が意図して閉じている。そこで、有無を当てようとせず、公開の指針に沿って次の 4 つを組み合わせる（F-G95）。

1. ログインの直後に、BFF が P で、保険会社（ログインサーバー）にある本人の passkey の一覧を、認可サーバーから読む。画面は、一覧を `signalAllAcceptedCredentials` で端末に伝え、保険会社が忘れた古い passkey を、端末に片付けてもらう。
2. 一覧が空なら、ログインの後に、この端末で passkey を作るかを尋ねる。利用者は「作る」か「後で」を選ぶ。
3. 画面の「パスキー」の欄に、一覧と、作成と削除を置く。使えなくなった端末（なくした、買い替えた、端末の設定で消した）の登録を、その端末なしで消せるようにする。そのために、次のようにする。
   - **見分ける:** 名前を、作った環境と日時にする（例: 「Windows・Chrome で作成（日時）」）。端末を表す「この端末の」とは書かない。一覧は保険会社にある全ての端末の分だからである。申込みの署名に使えた passkey の識別子を端末に覚えさせ、一覧で「この端末で使ったパスキー」の印を付ける。
   - **消す:** 各行の「消す」は、ログインサーバーに削除を頼む（`delete_credential`）。ログインサーバーが、名前を示した確認の画面で本人に確かめてから消す（F-G97）。認可サーバーには、書き換えの役を持たせない。
   - **作る:** ボタンは「パスキーを作る」とする。同じ端末で、使える passkey があるうちは、重ねて作らせない（登録の画面で既存の passkey を除外する。F-G97）。使えなくなったときに作ると、端末は同じ利用者の古い passkey を置き換える（端末によっては追加する）。
4. 署名を頼むときは、一覧にある識別子を指定し、古い passkey では署名させない。

端末に「この端末で passkey を作った」と覚えさせる仕組みは、やめる。保険会社が passkey を忘れても端末は覚えたままで、作り直す道を閉ざしたためである。

## 退けた案
- パスワードでサインインした人に作成を促す（ID トークンの `amr` で見分ける）: Keycloak 26.8.1 の標準の流れでは、2 つを区別できない（F-G96）。区別には、ログインの流れを作り替える必要がある。
- ログインの直後に、何かに署名させて確かめる: ログインのたびに Windows Hello の確認が 1 回増える。passkey でログインした結果は顧客のアプリに届かず、全員に確認を求めることになる。指針にもない。
- 端末が自分の passkey の識別子を覚え、保険会社に有無を聞く: 登録の直後の識別子の取り違えがありうる。利用者が端末から消した場合は分からない。指針にない工夫で、仕組みが増える。
- 追加のボタンを、ログインの間いつも出す: 登録済みでも登録を求められているように見える。「パスキー」の欄に、一覧と一緒に置けば、意味が分かる。
- 削除を、認可サーバーが管理の API で行う: 利用者を書き換える役（`manage-users`）が要る。Keycloak には passkey の削除だけの役がなく、パスワードの変更や利用者の削除までできる。
- 削除を、ログインサーバーのアカウントの画面に任せる: アカウントの画面の経路を、入口へ足す必要がある。画面も、顧客のアプリと別になる。消すのはログインサーバーで、`delete_credential` と変わらない。
- 最後に使った日を一覧に出す: Keycloak は使った日時を残さない。保険会社のシステムに記録を足す必要があり、今回は入れない。

## 影響
良い: 保険会社が passkey を忘れたとき（ログインサーバーの再起動など）に、作成を促せる。古い passkey は、端末が対応していれば片付く。端末の記録の食い違いが起きない。

悪い面は、次のとおりである。
- 別の端末の passkey が保険会社に残っていると、この端末に passkey がなくても促さない。そのときは、署名に失敗して、「パスキー」の欄から作る。
- Windows の VS Code に内蔵されたブラウザと Windows Hello では、保険会社の登録を消しても、端末の passkey は消えなかった（F-G98）。その passkey を使うと unknown user になり、作り直すと置き換わる。ほかのブラウザで消えるかは、確かめていない。
- ログインのたびに、認可サーバーとログインサーバーへの問い合わせが 1 往復増える。
- 一覧には、passkey の識別子と名前と、ログインサーバーの中の ID が載る。本人にだけ返し、公開鍵は返さない。
- パスワードを知った者は、passkey を作ることも、消すこともできる。作成や削除の前に、強い方法で確かめ直すことは、今回は入れない（F-G95 の checklist は、作成の前の確かめを勧める）。
- 同じ環境の端末が 2 台あると、名前だけでは見分けられない。「この端末で使ったパスキー」の印は、署名した端末にしか付かない。
- 名前の環境は、ブラウザの情報から作る。偽れるので、目安にとどまる。
- 消した passkey で署名済みの申込みは、そのまま有効である。保険会社のシステムは、受け付けるときだけ署名を確かめ、監査は署名を確かめ直さない。
