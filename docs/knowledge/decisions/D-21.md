# D-21. トークンを結ぶ鍵は、サービス単位とする。複製ごとに分けない

## 理由
複製は、冗長性と可用性のために持ち、どの複製が受けても同じに振る舞う。SPIFFE も、同じ仕事をする複製をまとめて 1 つの身元にする（F-G56）。送信者への結び付けの目的は、鍵を持たない者に、盗まれたトークンを使わせないことである（F-G57）。同じサービスの複製は、この「鍵を持たない者」に当たらない。

## 退けた案
- Pod ごとに SPIFFE ID を分ける（登録と運用が、複製の数だけ増える）
- B と C も、Pod ごとの鍵の DPoP にする（mTLS の証明書と別の鍵を、全ての Pod で持つ）

## 影響
良い: 複製の数や置き場所によらず、身元と結び付けの規則が同じになる。悪い: 乗っ取られた複製は、同じサービスのトークンを使える。複製どうしの隔離が前提になる（architecture の 7 章）

## 詳しい理由
SPIRE は、ノードが違う複製には、別の SVID（別の鍵）を配る（F-G53）。この区別は、防御として頼らない。複製の間でトークンを共有するときは、別のノードの複製が使うと拒否されるので、サービス単位の鍵を配る仕組みを先に決める。
