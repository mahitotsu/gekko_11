# D-38. 監査サービスは、ログインサーバーへのクライアント認証に、SPIRE の JWT-SVID を使う（Keycloak の federated-jwt）

## 理由
秘密の値を配らない方針（D-31）を保つ。Keycloak の client-x509 は SPIFFE の URI SAN を見ないので、ほかのサービスと同じ mTLS にはできない（F-G81）。JWT-SVID なら、同じ SPIFFE ID で認証できる。

## 退けた案
- client_secret: 秘密の値を配って守る手間が増える
- 公開クライアントと PKCE: 監査の画面のクライアントを認証しなくなる
- Keycloak に SPIFFE の証明書を読む認証の部品を足す: 製品の中の自作が増える

## 影響
良い: 監査サービスは秘密の値を持たない。悪い: preview の機能に依る。SPIRE に bundle の受け口と、使い捨ての TLS の証明書が増える。監査サービスの Pod に spiffe-helper が増える。
