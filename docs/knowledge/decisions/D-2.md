# D-2. AI の動作は、token exchange の委任で表し、成り代わりにしない

## 理由
委任では、本人と行為者の両方がトークンに残る。成り代わりでは、区別できなくなる（F-G1）

## 退けた案
AI の資格での呼び出し。本人のトークンの流用

## 影響
良い: 経由が記録に残る。悪い: 発行側が `act` を付けなければ効かない

## 詳しい理由

### 委任の範囲は、委任と範囲の仕様で上回る
窓口では、代理人が申し込むとき、本人と代理人の両方の本人確認書類が要る（I-B6）。DX では、token exchange の**委任**を使う。本人（`sub`）の ID を保ったまま、AI が行為者（`act`）として動く（F-G1）。委任の範囲は、RAR の `authorization_details` で表す（F-G2）。

上回る理由は 3 つある。範囲が機械的に適用される。行為者の連鎖が、入れ子の `act` で記録に残る（F-G1）。成り代わり（区別できなくなる）を避けられる（F-G1）。

紙の捨印は、相手に訂正の権限を事前に与え、重要事項の無断の書き換えを許す（I-A4）。DX にも同じ構造の悪い実装がある。広い範囲の委任を一度で与えることや、内容を示さずに署名させることである（推定）。

**前提:** 本人が、認可サーバーに直接ログインし、取決めの範囲を載せたトークン A を受け取る。アクセス制御は、最も外側の行為者だけを見る（F-G1）。過去の行為者は、判断でなく記録に使う。
