# D-2. AI の動作は、token exchange の委任で表し、成り代わりにしない

## 理由
委任では、本人と行為者の両方がトークンに残る。成り代わりでは、区別できなくなる（F-G1）

## 退けた案
AI の資格での呼び出し。本人のトークンの流用。

## 影響
良い: 経由が記録に残る。悪い: 発行側が `act` を付けなければ効かない。

## 詳しい理由

### 委任の範囲は、委任と範囲の仕様で上回る
窓口では、代理人が申し込むとき、本人と代理人の両方の本人確認書類が要る（I-B6）。DX では、token exchange の**委任**を使う。本人（`sub`）の ID を保ったまま、AI が行為者（`act`）として動く（F-G1）。委任の範囲は、RAR の `authorization_details` で表す（F-G2）。

上回る理由は 3 つある。範囲が機械的に適用される。行為者の連鎖が、入れ子の `act` で記録に残る（F-G1）。成り代わり（区別できなくなる）を避けられる（F-G1）。

紙の捨印は、相手に訂正の権限を事前に与え、重要事項の無断の書き換えを許す（I-A4）。DX にも同じ構造の悪い実装がある。広い範囲の委任を一度で与えることや、内容を示さずに署名させることである（推定）。

**前提:** 本人が、認可サーバーに直接ログインし、取決めの範囲を載せたトークン A を受け取る。アクセス制御は、最も外側の行為者だけを見る（F-G1）。過去の行為者は、判断でなく記録に使う。

### 比べた標準
取り次ぎの各段で、顧客の代理であることを引き継ぐ方法として、次を比べた。
- **token exchange（RFC 8693、F-G1）:** 採る。RFC で、段ごとに宛先を絞って替え、`act` に経由を積める。
- **Transaction Tokens（F-G25）:** 1 つの信頼の領域の中で、利用者と認可の文脈を引き継ぐ。保険会社の側（事務サービスから保険会社のシステム）に当てはまりうるが、草案なので追跡にとどめる。
- **identity chaining（F-G26）:** 信頼の領域をまたぐ引き継ぎ。営業 AI エージェントと保険会社が別の領域になる場合の候補だが、草案なので追跡にとどめる。
- **AI エージェントの委任の草案（F-G29）:** 期限が切れ、作業部会に採択されていない。

### `act` を積む理由と、前提
`act` を積まずに、`sub` を保ったまま、要求したクライアントを `azp` で示す方式もある。ただし、`azp` は直前に要求したクライアントしか示さない。トークン C の `azp` は事務サービスになり、保険会社のシステムは、営業 AI エージェントが取り次いだことをトークンから知れない。そうなると、要件 8（登録の確認）と要件 12（誰が取り次いだかを残す）を、事務サービスの言い分に頼って満たすことになる。そこで、`act` を積む。

- **肥大化しない:** 段は、営業 AI エージェント、事務サービス、保険会社のシステムに決まっていて、入れ子は最大 2 段である。
- **入れ子の扱い:** RFC 8693 は、トークンを受け取る側のアクセス制御で、入れ子の過去の行為者を判断に使わず、情報として扱うよう定める（F-G1）。保険会社のシステムは、入れ子の行為者で判断しない。連鎖の中に登録の外れた者がいるトークンは、発行した認可サーバーが、有効性の問い合わせで無効と答え、保険会社のシステムはその答えに従う（P-13）。入れ子の行為者は、記録に残す（D-9）。
- **実装の前提:** 認可サーバーが、`act` を積む委任に対応している必要がある。Keycloak 26.8 では、この機能は preview で、既定では無効である（F-G30）。このリポジトリは、Spring Authorization Server を使い、`act` の入れ子を拡張点で書く（D-19、F-G42）。

### 代理は `actor_token` と `may_act` で認可する
替えを頼む者は、自分のトークンを `actor_token` として出す。出されたトークンには、代理として認めた者を `may_act` で載せる。認可サーバーは、`actor_token` の `sub` が `may_act` と一致しなければ拒む。A の `may_act` は、顧客が同意した営業 AI エージェント、B の `may_act` は事務サービスである。PingOne Advanced Identity Cloud と Spring Authorization Server は、この確認を標準で持つ（F-G40、F-G42）。結び直しの前提となる代理の認可も、これで行う（D-7、F-G43）。
