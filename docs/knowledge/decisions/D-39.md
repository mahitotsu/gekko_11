# D-39. Keycloak の拡張は、secure では、取決めの範囲の形の確かめと、A の発行の記録だけにする。防御を外す部品は、vulnerable の jar にだけ入れる

## 理由
製品に任せる意味を保つため、設定でできないことだけを足す。取決めの範囲は、製品の SPI に形の確かめを登録すれば、製品が A に載せる（F-G78）。A の発行の記録は、監査の連鎖（D-17）に要るので、マッパーが `jti` を読んで書き出す（F-G79）。

## 退けた案
- `client_request_param_` の値を、マッパーで主張に写す: 調べた段階の案である。製品の SPI のほうが、認可の要求の段階で形を断れる
- 製品の成功のイベントのログから記録を作る: 書き出す欄が製品に依り、`jti` を確かめられていない
- 管理の API で防御を外す: secure にも管理の認証情報が要る

## 影響
良い: secure の拡張は小さい。悪い: 使う SPI は製品の内部の扱いで、版を上げると変わることがある（F-G78）。Keycloak の版は固定し、上げるときはクラスタのテストで確かめる。
