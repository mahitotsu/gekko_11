# 用語集

保険の募集の用語と、提案型の設計で追加する仕様の用語を説明する。

**この文書の読み手:** 全ての文書（[AI に取引を任せるときに、確かめるべきこと](purpose.md)、[アーキテクチャ](architecture.md)など）に出てくる用語の意味を、確かめたい人。窓口の用語の表には、デジタルの言葉を入れない。仕様の用語は、領域に依らない標準のもの、提案型の設計で追加する標準のもの、この設計での整理、この設計での仮称に分けて、下の表にある。

文書では、初出でこの用語集にリンクするか、ここの呼び名を使う。同じ概念は同じ語で書く。

## 窓口の用語
| 用語 | 意味 |
|---|---|
| 営業員（募集人） | 顧客に保険を勧め、申込みを受ける人。登録が要る（I-F1） |
| 顧客（契約者） | 保険に申し込み、保険料を払う人 |
| 被保険者 | 保険の対象になる人。申込書に署名する場合がある（I-B3） |
| 申込書 | 保険に申し込むための用紙。顧客が署名する |
| 申込書の写し | 申込内容を記した控え。顧客に交付する（I-A1） |
| 提案（案） | 営業員が示す、保障内容や保険料の組み合わせ。複数を比較して示すことがある |
| 比較推奨販売 | 複数の保険会社の商品を比較して勧めること。推奨の理由を説明する（I-A2） |
| 意向把握 | 顧客の希望や事情を聞き取ること。それに沿った提案につなげる（I-B2） |
| 意向確認書面 | 顧客の意向と、案が意向に合う理由を記した書面。交付し、保存する（I-B2） |
| 契約概要 | 保険の仕組み、保障内容、保険期間、保険料などを記した書面（I-C1） |
| 注意喚起情報 | クーリング・オフ、告知義務、免責事由など、注意を促す内容を記した書面（I-C1） |
| 告知 | 健康状態などを、会社に伝えること。書面で、本人が行う（I-B3） |
| 代筆 | 顧客に代わって、他の人が記入すること。自筆が困難な人の口頭の申込みに限る例外（I-B1） |
| 本人確認書類 | 運転免許証、マイナンバーカードなど、本人を確かめる書類。コピーの提示だけでは認められない（I-B6） |
| 取引時確認 | 法令に基づき、本人確認書類で氏名・住居・生年月日を確かめ、取引の目的と職業を聞くこと（I-B6） |
| 確認記録 | 取引時確認を行った記録。書類の写しなどを添える（I-B6） |
| 被保険者の同意 | 他人を被保険者とする死亡保険などで、被保険者が契約に同意すること。なければ効力が生じない（I-B7） |
| 氏名・所属の明示 | 営業員が、顧客に氏名や所属を明らかにすること（I-B8） |
| 保険料領収証 | 保険料を受け取ったとき、会社所定の様式で渡す書面（I-G3） |
| 返戻 | 郵送した郵便物が、届かずに戻ってくること。戻らないことで、住所の実在を確かめる方法がある（I-G2） |
| 事務担当 | 営業員から回ってきた申込書を、会社の側で処理する人 |
| 事務センター | 会社の事務を担う部署。営業員から回付された申込書を点検する。運用の細目は確認できなかった（I-D2） |
| 回付 | 申込書を、営業員から事務担当へ回すこと。運用の細目は確認できなかった（I-D2） |
| 証券（保険証券） | 契約が成立したときに、会社が契約者へ交付する書面。契約内容を記す（I-G2） |
| 直送 | 事務センターが、営業員を通さずに、証券を顧客へ直接送ること。代理店を介さない交付の措置は実在し、営業員への適用と事務センターの運用は想定である（I-G2） |
| 加入の査定（引受査定） | 申込みの後に、会社が加入を認めるかを判断すること（I-D1） |
| クーリング・オフ | 申込みの後に、一定期間内なら無条件で取り消せる制度（I-E1） |
| 不祥事件 | 営業員などによる不正な行為。届出と通知の対象になる（I-F3） |
| 伏在調査 | 表に出ていない類似の不正がないかを調べること（I-F3） |
| 所属保険会社等 | 営業員が所属する保険会社。営業員が与えた損害を賠償する責任を負う（I-H1） |

## 仕様の用語（領域に依らない）
| 用語 | 意味 |
|---|---|
| DX | デジタル技術で、業務や仕組みを置き換えること。この文書群では、窓口の統制をデジタルで実現することを指す |
| 真正性 | 主体や情報が、主張するとおりのものであるという特性。情報セキュリティの用語で、取引についての定義ではない。電子帳簿保存法では「真実性」と呼ぶ（C-4）。この文書群は、「取引が確かなもの」と平易に書く |
| 代理権 | 本人が代理人に与えた、本人に代わって取引をする権限。代理人が権限の範囲内で、本人のためにすることを示して行った行為は、本人に効力を持つ（民法 99 条。C-5） |
| 認可サーバー、リソースサーバー | 権限の証拠（トークン）を発行する側と、それを受け取って操作を実行する側。この設計では、どちらも保険会社が運営する |
| バックエンド | 申込みを受け取って検証し、実行する側のサービス。リソースサーバーに当たる。この設計では、保険会社のシステム（insurer-backend）がこれに当たる |
| クレーム | トークンに入っている、1 つ 1 つの情報。`sub`（本人）、`aud`（宛先）、`act`（行為者）など |
| challenge | サーバーが渡す使い捨ての値。署名に含めて、署名の再利用を防ぐ（F-G8） |
| nonce | 一度しか使えない値。提出された依頼の再利用を防ぐ |
| origin | ウェブサイトの識別（プロトコル、ホスト、ポート）。passkey の鍵は origin に結び付く（F-G8） |
| Relying Party | passkey を使って利用者を確かめる側のサービス |
| JCS | JSON の書き方を一つに揃える規則（RFC 8785）。同じ内容は、同じ文字列になるので、ハッシュが安定する（F-G20） |
| プロンプトインジェクション | 入力に紛れた指示で、AI が意図しない動きをすること |
| passkey（パスキー）、WebAuthn | 利用者の端末にある鍵で署名して、本人であることを示す仕組み。鍵はサイトの origin に結び付く（F-G8） |
| OAuth 2.0 | 利用者が、ある装置に、自分の代わりに別のサービスを使う権限を渡す仕組み |
| アクセストークン（トークン）、JWT | 権限を渡した証拠となる、署名つきのデータ。誰が（`sub`）、どの宛先に（`aud`）使えるかなどを含む |
| `act`（行為者） | 本人の代わりに動いた者を表すクレーム。入れ子で連鎖を表す（F-G1） |
| token exchange | あるトークンを、別の宛先のトークンに替えてもらう仕組み（RFC 8693、F-G1） |
| RAR（Rich Authorization Requests） | 「この種類の保険を、この給付額まで」のような細かい権限を表す仕組み（RFC 9396、F-G2） |
| step-up（追加認証） | 取引に応じて、認証の強さや新しさを求め直す仕組み（RFC 9470、F-G3） |
| DPoP | トークンを送信者の鍵に結び付け、盗まれたトークンを使えなくする仕組み（RFC 9449、F-G4） |
| mTLS | 通信の両側が証明書で相手を確かめる仕組み。トークンを証明書に結び付けられる（RFC 8705、F-G5） |
| CIBA | 取引を始める端末と、承認する端末を分ける仕組み（F-G6） |
| SPC（Secure Payment Confirmation） | 取引内容をブラウザの画面に出して、署名させる仕組み（F-G7） |
| MCP | AI エージェントが外部の機能を呼ぶための取り決め。呼び出せる操作の一覧を持つ |
| 監査ログ | 誰が何をしたかの記録。後から追うために残す |

## 提案型の設計で追加する仕様の用語（標準）
| 用語 | 意味 |
|---|---|
| 確認済みの属性（verified_claims） | 本人確認の方法、日時、根拠を添えた属性。保険会社が署名して持つ（F-G11） |
| トークンの有効性の問い合わせ（introspection） | 受け取った側が、トークンが今も有効かを、発行元に問い合わせる仕組み（F-G9） |
| トークンの失効（revocation） | トークンを、発行元に依頼して無効にする仕組み（F-G10） |
| クライアント登録 | AI エージェントなどを、認可サーバーに登録すること。識別子（`client_id`）が発行され、名称、権限の範囲、公開鍵などが結び付く（RFC 7591、F-G12）。営業員の登録に当たる |

## この設計での整理（標準の用語ではない）
| 言葉 | 意味 |
|---|---|
| 顧客のアプリ | 顧客が使うアプリ（customer-app）。案を表示し、利用者の鍵で署名し、直送された契約内容を写しと照合する。窓口の顧客の手元に当たる |
| 営業 AI エージェント | 顧客の意向を聞いて案を示し、顧客が選んで署名した申込みを、顧客の代理として事務サービスへ運ぶ AI（sales-agent）。窓口の営業員に当たる。鍵も記録も持たない |
| 事務サービス | 営業 AI エージェントが呼ぶ MCP サーバー（insurer-mcp）。自分宛てのトークンだけを受け付け、トークンを替えて保険会社のシステムを呼ぶ。窓口の事務担当に当たる |
| 保険会社のシステム | 案に署名し、トークンと署名の連鎖を検証し、契約の記録を作り、契約内容を直送するサービス（insurer-backend）。窓口の保険会社のシステムに当たり、事務担当の点検も担う |
| 認可サーバー | 本人確認の記録を持ち、トークンを発行し、回付のたびに替えるサービス（insurer-auth）。窓口の役にはなく、証明を発行する保険会社に当たる |
| 取決めの範囲 | 営業 AI エージェントが扱える契約の種類と上限。トークンの `authorization_details`（RAR）で表す。替えたトークンでは、引き継ぐか狭めるだけにする |
| トークン A、B、C | 認可サーバーが出す、3 つのアクセストークン。A は顧客のアプリが営業 AI エージェントを呼ぶ許可、B は営業 AI エージェントが顧客の代理として事務サービスを呼ぶ許可、C は事務サービスが顧客の代理として保険会社のシステムを呼ぶ許可の証明 |
| 回付される一式 | 意向確認書面、署名済み申込、本人確認の属性の参照、被保険者の署名、登録の識別子をまとめたもの。保険会社のシステムが検証する |
| 署名済み申込 | 顧客が利用者の鍵で署名した申込。顧客のアプリが写しを保存する |
| 保険会社のシステムでの検証 | 事務担当の点検に当たる。署名の連鎖、登録の有効性、範囲を確かめる |
| 決定論的な取り込み | 署名済み申込から、同じ入力に同じ結果を返すプログラムが、契約の記録を作ること。人や AI は内容を入力しない。記録は再計算で照合できる |
| アプリでの自動照合 | 顧客のアプリが、保存した写しと、保険会社から届いた契約内容を照合すること |

## この設計での仮称（標準の用語ではない）
| 仮称 | 意味 |
|---|---|
| 署名つきの提示 | 保険会社が、示す案の内容に署名したもの。AI は案を示せるが、各案の中身は変えられない |
| 選択の結び付け | 顧客が選んだ案の識別子と、示された案の全体の識別子を、顧客の署名の対象に含めること |
| 提示集合の識別子 | 示された案の全体から計算した値。案の追加や削除があれば、値が変わる |
| 直送の通知 | 保険会社が、AI を経由せず、顧客の登録済みの経路へ送る通知。顧客のアプリが、保存した写しと自動で照合する |
| 取消の窓口 | 取消を受け付ける場所。AI を経由せず、本人から保険会社へ直接届く経路 |
| 保険会社が署名した登録情報 | 保険会社が、AI の氏名・所属・扱える範囲に署名した記録。顧客のアプリが検証して表示する。近い標準は software statement（F-G12）だが、顧客に見せる用途は想定外とみられる |
