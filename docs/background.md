# このリポジトリの出発点

このリポジトリを作ろうと考えた動機と、題材を保険の窓口に決めた経緯、最初のメモの事実確認の結果を残す。

**この文書の読み手:** 作者と、リポジトリの経緯を知りたい人。読んだ後に、なぜ票の検証と発行の両方を扱うのか、なぜ保険の窓口を題材にしたのか、最初のメモのどこを直したかが分かる。

## 要旨
- **動機（作者の認識）:** frontend → AI Agent → MCP → backend の多段呼び出しが当たり前になり、JWT の検証と発行の不備が現実の危険になった。
- **目的:** token exchange の実装を提供することではない。JWT を正しく検証すること、正しく検証できる JWT を発行することの重要性を伝える。
- **手段:** DX 前の保険の窓口の統制を調べ、その目的に対して、JWT の検証と発行がどう対応するかを、例えで示す。悪い実装と良い実装を、実装で比べる（[scenarios.md](scenarios.md)）。
- **進め方:** 調査を先に行い、その根拠から例えと設計を作る。実装から例えを作らない。
- **最初のメモの誤りは、直した:** 下の表に示す。

## 動機の整理
A → B → C と呼ぶとき、次の問題が起きる。

- B が C を呼ぶ票を、B 自身の資格で取ると、C は利用者本人を判定できない（本人の消失）。
- 本人の票を C にそのまま流すと、宛先が違う票を使うことになる（宛先違いの流用）。
- 経由した B が本人を名乗って票を取り直す方式では、B（AI）による `sub` の書き換えを防ぐ仕組みが要る。

frontend から全ての API を直接呼ぶ構成では、この問題は目立たなかった。AI エージェントと MCP が間に入る構成では、多段が前提になるため、起きやすい（作者の認識）。

## 題材を、銀行の振込から保険の募集に替えた経緯
1. **最初は銀行の振込で例えを作った。** しかし、実装から例えを作ったため、例えが現実の窓口と食い違った。
2. **DX 前の窓口の統制を、先に調べる方針に改めた。** 窓口が実現したかった目的を、調べて整理し、それを DX の手段がどれだけ確実に実現できるかで評価する。
3. **銀行の窓口の調査では、代筆の運用が公開資料から確認できなかった。** また、「選ぶ」操作がなく、AI エージェントが案を示し、本人が選んで承認する構造と合いきらなかった。
4. **そこで、営業員が複数案を示し、顧客が選んで署名する保険の募集に替えた。** 保険の募集は、意向把握、比較推奨、申込書の写しの交付などが、監督指針に公開されている。
5. **銀行編の調査は、領域に依らない部分を保険編の設計に移し、削除した。**

調査と設計は、[story.md](story.md) の例えの根拠である。結果は [research/](research/report.md) にある。

## 最初のメモから直した点
| 最初のメモ | 事実確認の結果 |
|---|---|
| 検証するのは `sub, aud, scope, iss` あたり | 署名と `alg` の固定、期限、`typ` も要る。基本仕様（RFC 7519）では任意の項目を、アクセストークンの規則（RFC 9068）が必須にする（F-G13、F-G15）。`scope` は認可に使う値。`sub` は、アプリケーションで有効な主体かを検証する（F-G14） |
| B が C 用に取るトークンの `sub` は B になるしかない | client credentials ならそうなる（`sub` は、所有者が関与しない場合、クライアントを示す。F-G15）。token exchange なら `sub` は本人のまま、`act` に B が残る（F-G1） |
| 取り直すと `sub` を AI が改ざんするリスクがある | 認可サーバーが元の票を検証して発行する設計なら、AI は `sub` を偽造できない（推定）。実際の危険は、ツールの引数の「誰の契約か」を信じる実装 |
| 振込用紙のメタファーが JWT に対応する | 用紙（申込みの内容）は API のパラメータに対応する。票に当たるのは、窓口に来たことを示す書類である。申込みの内容の改ざん防止は、票とは別に要る（[story.md](story.md)） |
| 受け取ったトークンを、MCP が別の API に使ってよいか | MCP の認可仕様は、受け取ったトークンの素通しを禁じる（F-G17）。次の宛先の票に、替えてもらう |

仕様の記述は、一次資料で本文を確認したものと、未確認のものがある。確認の状況は、[事実集](research/findings.md)にある。
